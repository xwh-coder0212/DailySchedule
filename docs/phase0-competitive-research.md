## 0. 结论摘要（TL;DR）

1. **市场被切成互不通气的两半。** 记账 App 完全不关心你的时间，时间管理 App 完全不关心你的钱。没有任何一个主流产品把「时间账」和「金钱账」放进同一条时间轴。
2. **少数 all-in-one 产品（时光序、TickTick）是"功能并列"而不是"数据融合"。** 记账模块和专注模块各存各的表，共用底部导航栏而已。这恰好是 DailySchedule 的空隙。
3. **真正的杀手不是功能少，是记录摩擦。** 记账失败原因高度一致：解锁→找 App→点记账→输金额→选分类→选账户→保存，七八次点击、半分钟一笔。消费是碎片场景，摩擦直接等于漏记，漏记直接等于放弃。
4. **"计划"类工具过剩，"实录"类工具稀缺。** 日历/Todo/预算都在描述"我打算怎么做"，几乎没有工具诚实地记录"我实际做了什么"。DailySchedule 应该站在"回顾"这一侧。
5. **游戏化与社交是留存的糖，不是留存的根。** Timing 因首页短视频化导致大规模弃坑，Forest 因订阅化评分下滑。外部动机失效后，产品必须靠"数据本身有价值"留住人。
6. **对 DailySchedule 最危险的路是"功能齐全"。** 时光序已经把记账+专注+日记+习惯+纪念日都做了，用户评价是"中规中矩、部分功能繁琐"。做全=做平庸。

## 1. 研究方法与样本边界

**方法**：多轮公开检索（2026 年评测、Google Play 商店数据、开发者文档、用户评论聚合、Android 工程实践资料），横向比较后归纳。

**样本分组**：

- A 组 · 个人财务：Monefy、Money Manager（Realbyte）、Wallet（BudgetBakers）、Spendee、Bluecoins、YNAB、微信生态轻量记账（小程序/公众号）
- B 组 · 专注与学习计时：Forest、番茄ToDo、潮汐、Costudy、Timing、番鱼、不做手机控
- C 组 · 时间追踪：aTimeLogger、Toggl Track、Timesheet、Jiffy、Gleeo、爱今天
- D 组 · 任务/日历/习惯：TickTick、Todoist、Google Calendar、Streaks、Habitica、小日常
- E 组 · 本土 all-in-one：时光序

**研究局限（必须坦白）**：

- 主要依据 2026 年公开评测、商店评分与评论聚合，**未逐一安装实测**，体验类结论属于二手推断。
- 部分国内产品（Timing、Costudy、时光序）的公开资料更新到 2020–2021 年，其当前形态可能有变化，结论按"历史教训"而非"当前状态"采信。
- 商店评分只能反映"愿意去打分的人"的意见，存在系统性偏差。

## 2. 市场分层：四个互不重叠的战场

```
                    关心"钱"
                        ▲
                        │
        Wallet/Spendee  │  Monefy / Money Manager
        YNAB / Bluecoins│  (纯记账，无时间维度)
                        │
   ─────────────────────┼─────────────────────► 关心"时间"
                        │
      Toggl / aTimeLogger│  Forest / 番茄ToDo / 潮汐
      (时间追踪/计费)    │  (专注计时，无金钱维度)
                        │
                        │  ★ DailySchedule 的空隙：
                        │    同一条时间轴上的两个账本
```

关键判断：**这个空隙不是"没人想到"，而是"想到了但做成了并列"**。时光序做了记账+专注，但用户评价是"每个模块都不深"。

## 5. 用户痛点（按严重度排序）

| # | 痛点 | 证据 | 对 DailySchedule 的含义 |
| --- | --- | --- | --- |
| P1 | **记录摩擦杀死习惯**。七八次点击记一笔，碎片场景根本记不住 | 多篇 2026 年中文分析："绝大多数人记账撑不过 10 天"，主因是工具太重而非自制力 | 首页必须有一键入口；金额输入要能盲打；分类要能 0 思考命中 |
| P2 | **漏记一两次 → 全盘崩溃 → 彻底放弃** | "一旦漏记一两笔，就产生全盘崩溃的心态，直接摆烂" | 必须支持事后补录与时间可编辑；绝不用"连续天数"作为唯一激励 |
| P3 | **只记不复盘 = 无效记账** | "记账变成自我感动式任务，对存钱没有实质帮助" | 统计不是附加功能，是主功能。第一屏就要能看见结论 |
| P4 | **数据在云端，换机/停服即失** | "更换手机需要手动备份导出，多年账单存在丢失风险"；Habitica/Strides 用户反馈同步失败静默丢数据 | Local-first + 一键导出，是信任基础 |
| P5 | **广告、理财营销、付费墙** | Money Manager 含广告；Spendee/YNAB 核心功能付费 | 自用 App 天然无此问题——这是个人项目的巨大优势 |
| P6 | **计划 ≠ 实录** | 日历/Todo 描述的是"打算做什么"，不是"实际做了什么" | 这是 DailySchedule 的定位缝隙 |
| P7 | **时间统计只覆盖"专注 App 内的时间"** | 番茄钟给出"5 个番茄"，但不等于"今天学了 6h40m"，更不等于"我今天做了什么" | 时间轴要能容纳非专注事件（消费也是事件） |
| P8 | **游戏化失效后无留存** | Timing 因首页短视频化引发大规模弃坑；Forest 订阅化导致评分下滑 | 靠数据价值留存，不靠外部刺激 |
| P9 | **分类过细导致决策疲劳** | "Was that dinner dining out or groceries?" —— 细粒度分类承诺洞察，实际是持续的小决策成本 | 分类体系要扁平、克制、可后置调整 |
| P10 | **all-in-one 变成 all-shallow** | 时光序评价："中规中矩……缺少互动和内容"、"部分功能有些繁琐" | 功能数量不是目标，融合深度才是 |

## 6. 六个关键问题的回答

### 6.1 哪些功能已成为行业标准（不做即被视为残缺）

**记账侧**
- 金额输入即完成（最多补一个分类），3 秒内
- 分类 + 图标 + 颜色三件套
- 日/周/月/年 周期切换与汇总
- 分类占比可视化
- 编辑/删除历史记录
- 离线可用 + 数据导出

**时间侧**
- 正计时 + 暂停/继续 + 结束
- 项目维度计时
- 后台持续（常驻通知）
- 日/周/月/年 与项目累计统计
- 事后补录与编辑

**通用**
- Material 设计语言、深色模式
- 首屏即结论，而非入口列表

### 6.2 哪些功能实际很少被使用

| 功能 | 判断依据 |
| --- | --- |
| 复式记账 / 多账户 / 转账 | 个人用户占比极低，Money Manager 的核心卖点恰是它最重的地方 |
| 资产、净值、投资管理 | 非目标用户；YNAB/Monarch 的重度模块 |
| 银行自动同步 | 隐私顾虑 + 链接易断 + 国内覆盖不确定 |
| 共享账本 / 多人协作 | 单人使用场景为零 |
| 二级子分类 | 决策成本 > 分析收益 |
| 分类预算 / 滚动预算 | 月度总预算已覆盖 80% 需求 |
| 估算番茄数 / 任务工期 | 极少有人持续维护 |
| 标签系统 + 智能清单 + 筛选器 | Todoist 重度用户才用 |
| 游戏化成就 / 排行榜 | 新鲜感 3 周内衰减 |
| 锁机 / 强制专注 | 有用但权限重、争议大 |

### 6.3 哪些功能容易造成 App 复杂化

1. **多账户 + 转账 + 复式**：引入"这笔钱从哪来到哪去"，指数级增加状态与边界。
2. **任务嵌套层级**（项目→任务→子任务→检查项）：每加一层，UI 与导航复杂度翻倍。
3. **云同步与冲突解决**：多端修改同一条记录的合并策略，是独立的技术子系统。
4. **社交 / 排行榜**：需要账号体系、后端、审核、防刷。
5. **重复规则引擎**：RRULE + 例外 + 跳过 + 提前/延后，是完整的日历级复杂度。
6. **标签 + 筛选器 + 智能清单**：本质是查询语言，需要自己的 DSL 与索引。
7. **游戏化系统**：货币、等级、道具、活动，等于做了第二个产品。

> 结论：**上述 7 项，DailySchedule 第一版一项都不该碰。**

### 6.4 哪些设计非常值得借鉴

| 来源 | 值得借鉴的点 | 如何转化 |
| --- | --- | --- |
| **Monefy** | 一个大圆盘，点分类→输金额→完成 | 记账页用"分类九宫格 + 数字键盘"单屏完成，不做二级页 |
| **Monefy / Money Manager** | 无账号、离线可用、本地备份 | Local-first 是默认，不是选项 |
| **aTimeLogger** | 正计时 + 暂停 + 目标 + CSV 导出 | 时间记录的核心交互就照这个来，别发明新东西 |
| **Toggl Track** | 忘记开始也能事后补一个时间块 | "补录"是一等公民，不是补救措施 |
| **番茄ToDo** | 历史时间轴（很多人就为了回看这一天） | 强化为"Day Timeline"，且同时容纳时间与金钱事件 |
| **Timesheet** | 桌面小组件一键开始/停止 | 通知栏常驻 + 桌面小组件，把摩擦降到最低 |
| **爱今天** | 把时间分为"投资/固定/消耗"三类 | 项目分类可用类似思路（投资型 vs 消耗型） |
| **Google Calendar** | 时间块的视觉表达（但它是计划） | 借用视觉语法，填入实录数据 |
| **记账类通用** | 当日总额常驻可见 | 首屏数字要大、要即时反馈 |
| **TickTick** | 一个 App 覆盖多需求，降低切换成本 | 但只学"整合"，不学"堆功能" |

### 6.5 哪些设计不适合 DailySchedule

| 设计 | 为什么不适合 |
| --- | --- |
| 银行/支付账户自动同步 | 隐私敏感、需要后端、国内覆盖不确定，与 Local-first 冲突 |
| 投资与资产管理 | 不是目标用户的核心诉求 |
| 社交、自习室、排行榜 | 需要账号与服务端；外部动机衰减快；Timing 已证明反噬风险 |
| 锁机 / 强制专注 | 需 AccessibilityService（高危权限），与"自用轻量"定位不符 |
| 游戏化种树 / 成就 | 维护成本高，且对"看数据"型用户无价值 |
| 复式记账 / 多账户 | 复杂度远超收益 |
| 多端实时同步 | 第一版应完全避免（冲突解决是独立子系统） |
| streak 作为核心激励 | 断签即卸载，与"漏记也可补"的容错理念冲突 |
| 通用 Todo 管理 | 会把产品重心从"记录与回顾"拉向"计划与执行"，这是另一个战场 |

### 6.6 DailySchedule 的潜在差异化方向

**核心命题（一句话）**

> 不是"记账 + 番茄钟"，而是 **同一条时间轴上的两个账本**。

**六个具体差异化点**

1. **统一时间轴（Day Timeline）**
   学习时段与消费时点在同一条纵向时间轴上呈现。晚上打开，一眼看到"我这一天"：`08:30–09:10 数学` 与 `08:10 早餐 ¥8` 并列。这是目前没有任何主流产品做到的。

2. **双账本对称结构**
   时间账与金钱账共用同一套"项目/分类 + 周期统计 + 趋势 + 占比"的表达。降低认知成本：学会看时间统计，就会看消费统计。

3. **项目是长期资产，不是任务**
   "考研数学：累计 128h32m" 这种跨月跨年累计，是考研人群的核心资产。主流 App 要么按番茄计数，要么按周统计，缺少"这个项目我到底投入了多少"的长期视角。

4. **Local-first + 数据主权**
   不登录、不上传、可导出。在"数据在云端，换机即失"的普遍焦虑下，这是真实的信任优势。

5. **实录优先于计划**
   不重复做日历和 Todo。记录已经发生的事，而不是规划未发生的事。

6. **零摩擦入口**
   通知栏 + 桌面小组件：一键开始计时、一键唤起记账。把"七八次点击"压到"一次点击"。

**必须诚实说明的风险**

- 差异化 1、2 的**真实价值尚未验证**——"把时间和钱放在一条时间轴上"听起来很美，但可能只是视觉上的并列，未必产生新洞察。**这需要你在访谈中帮我确认：你晚上回顾的时候，真的需要看到消费和学习混在一起吗？还是分开两块更好？**
- 差异化 4（Local-first）意味着**换机需要手动导数据**，这是主动取舍，需要你接受。
- 差异化 5 意味着**放弃 Todo/日历市场**，产品会显得"不够全能"。

## 8. 阶段总结

### 已确定
- 市场空隙真实存在：时间账与金钱账的融合，且不是功能并列而是数据融合。
- 行业标准清单（见 6.1）：这些不做会被视为残缺。
- 应排除清单（见 6.3、6.5）：复式记账、多账户、银行同步、社交、锁机、游戏化、多端实时同步，第一版全部不做。
- 记录摩擦是第一杀手；事后补录是一等公民功能。
- Local-first 与数据可导出是信任基础。

### 未确定（需要你回答）
1. 计时模式：正计时 / 番茄钟 / 两者并存？
2. 消费是否需要关联到项目？
3. 是否需要 Todo / 待办层？
4. 数据策略：纯本地 / 本地+文件导出 / 云端？
5. 是否需要"目标与预算"这一层（计划层）？
6. 首屏信息优先级与 Timeline 的具体形态。
7. 考研周期结束（考完）之后，这个 App 对你还有用吗？——这决定了产品是"阶段性工具"还是"长期生活记录"。
