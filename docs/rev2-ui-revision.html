一个我替你定了、但你可以推翻的判断

原来「今日」页里的三数字（学习时长 / 消费 / 专注次数）和今日时间轴，我放进了统计页。

依据：导航只剩三项，而你对统计的定义是「对今日专注的时长进行记录」——"今日"的结论本来就属于统计。参照的待办页里也没有任何数字摘要，只有卡片。

如果你希望「今日」单独存在（比如从待办页顶部进入，或者作为统计页的第一屏），告诉我，我改回来。

四、关于「不做游戏化」

你之前说"不做游戏化"，指的是不引入一套与事实无关的虚拟状态来驱动你行动。具体就是不做这些东西：

属于游戏化，已排除

  • 连续打卡天数 / 连击 streak（断一天归零）
  • 等级、经验值、成长树
  • 成就徽章、奖章墙
  • 排行榜、好友对比、PK
  • 积分、抽奖、虚拟奖励、皮肤解锁
  • 目标完成率百分比 + 庆祝动画
  • 未完成时的提醒/催促/惩罚提示

不属于游戏化，本来就该做

  • 今日/本周/本月的时长与金额汇总
  • 占比环、趋势折线、分布柱状
  • 周热力图（只陈述"哪天有专注"，不判好坏）
  • 累计次数与累计时长
  • 番茄钟到点提醒

分界线在哪：看这个数字会不会"反过来评价你"。

  • 「本周专注 12 小时」——陈述事实，保留。
  • 「本周目标达成 70%，非常出色！」——它在评判你，且"出色"的标准是凭空定的，属于游戏化，排除。

这也正是你这次砍掉「定目标 / 养习惯」的原因：那两类待办的全部意义就是"达成率"，砍掉它们，整个 App 就没有任何地方需要虚拟评分了。

一个边界情况 你给的第二张参考图里，日历面板下方有个「70% 非常出色！」的庆祝卡。按上面的分界线，它属于游戏化。我按不做处理，如果你想要，单独说。

五、新功能：导出 Excel

技术上怎么做

项方案
文件格式 真 .xlsx（OOXML）。不引 Apache POI —— POI 依赖 java.awt，在 Android 上跑不起来且方法数会炸。改用 java.util.zip 手写最小 xlsx（6 个 XML 部件），零新增依赖、纯离线。
文件组织 一个 .xlsx，两个工作表：专注记录 / 花费记录。理由：一次 SAF 授权就够，Excel 里天然分表，"两类数据不混在一起"的诉求也满足。
若你坚持要两个独立文件，改起来只多一次授权弹窗。
保存位置 SAF（ACTION_CREATE_DOCUMENT），由你选目录，App 不申请存储权限。
联网 不联网、不上传。仍然是纯本地。

列定义

专注记录
日期按你的日切时刻归属

必须点破的一件事：Excel 不能当备份

Excel 是单向导出——只能出，不能进。换手机、丢手机之后，你没法把这份 xlsx 还原回数据库。

而「JSON 导出 / 导入」那条数据逃生通道，目前仍然是空的（09-09 排查时标的 P0 缺口）。

两者解决的是不同问题：

  • Excel 导出 —— 给你看、给你分析、能拿去别处用。本次已实现。
  • JSON 导出 / 导入 —— 保命。换机不丢数据。本次不做。

为什么不一起做：JSON 备份要连「导入」一起做才算数，而导入意味着版本校验、外键重建、 部分失败的原子性——那是一整套写库逻辑，和「写一个 xlsx」不是同一件事。 把它塞进这次改动里，会让一个本来可以稳定交付的功能被一个高风险功能拖住。 所以这次只交付 Excel，JSON 排在下一批，并且在界面上用红字明确写出「这不是备份」， 避免你把「导出成功」误读成「数据安全了」。
